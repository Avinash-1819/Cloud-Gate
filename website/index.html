Audited AWS Services

Real-Time Functioning AWS Security Services

Every check connects to live AWS APIs in read-only mode to extract ground-truth configurations. No sample data, no simulations, zero writes.

AWS IAM & Root Hygiene

LIVE AUDIT

Audits account-level identity perimeter, credential hygiene, and privileged policy attachments to block initial access vectors.

Live API: iam:GetAccountSummary, GetCredentialReport
  • Root account active CLI access keys CRITICAL
  • Root account lacking multi-factor authentication (MFA) CRITICAL
  • IAM console users without MFA enforced HIGH
  • Inactive console passwords (>45 days) & unused access keys
  • Over-privileged roles with AdministratorAccess or */*

Amazon S3 Storage Security

LIVE AUDIT

Inspects public bucket exposures, access control lists, and cryptographic enforcement across all buckets in the account.

Live API: s3:ListBuckets, GetPublicAccessBlock
  • S3 Block Public Access (BPA) missing or partially disabled HIGH
  • Public bucket policies or wildcard read/write ACLs CRITICAL
  • Buckets lacking default Server-Side Encryption (SSE-S3 / SSE-KMS)
  • Audit of bucket ownership controls & object lock retention

EC2 & IMDSv2 Metadata

LIVE AUDIT

Detects the exact root-cause architecture of major cloud breaches: internet-facing instances combined with attached IAM roles.

Live API: ec2:DescribeInstances (MetadataOptions)
  • Public IP instance with attached IAM Instance Profile CRITICAL
  • Tokenless IMDSv1 enabled (vulnerable to SSRF credential theft) CRITICAL
  • Enforces HttpTokens='required' (IMDSv2 session tokens)
  • Flags unencrypted EBS volumes & exposed compute instances

VPC Security Groups & Ports

LIVE AUDIT

Reads security group rules via the AWS API to detect dangerous inbound rules. Zero network packets or port scans are transmitted.

Live API: ec2:DescribeSecurityGroups (IpPermissions)
  • Management ports open to 0.0.0.0/0 (SSH 22, RDP 3389) CRITICAL
  • All ports/protocols exposed to the world (protocol -1) CRITICAL
  • Exposed databases: MySQL 3306, Postgres 5432, Redis 6379, Mongo 27017
  • Generates exact aws ec2 revoke-security-group-ingress commands

AWS KMS Key Governance

LIVE AUDIT

Audits cryptographic keys and automated lifecycle governance across Customer Managed Keys (CMKs).

Live API: kms:ListKeys, GetKeyRotationStatus
  • Customer Managed Keys without automatic annual rotation enabled
  • Disabled or scheduled-for-deletion active encryption keys
  • Overly broad key policies allowing unauthorized cross-account decrypt
  • Provides direct aws kms enable-key-rotation remediations

VPC Network Telemetry

LIVE AUDIT

Verifies network monitoring coverage to prevent unobserved lateral movement and data exfiltration channels.

Live API: ec2:DescribeVpcs, DescribeFlowLogs
  • VPCs operating without active VPC Flow Logs (network blind spots)
  • Default VPC posture and unused subnet hygiene
  • Flow log capture status (ALL traffic vs ACCEPT/REJECT filters)
  • CloudWatch Logs & S3 log destination delivery verification

CloudTrail Audit Logging

LIVE AUDIT

Ensures immutable forensic evidence is recorded for every AWS API call made across all active and inactive regions.

Live API: cloudtrail:DescribeTrails (Status & MultiRegion)
  • Zero CloudTrail trails active in connected account HIGH
  • Single-region trails allowing activity in other regions to go unlogged
  • Log file integrity validation (cryptographic hash verification)
  • S3 storage bucket logging and access protection

GuardDuty Threat Detection

LIVE AUDIT

Checks whether automated machine learning threat detection is actively monitoring VPC flow, DNS, and management events.

Live API: guardduty:ListDetectors (Active Status)
  • GuardDuty detector enabled / disabled across target regions
  • Handles subscription and opt-in states gracefully
  • Continuous monitoring for compromised IAM credentials
  • Detection of unauthorized cryptocurrency mining or port scans

AWS Credentials & Setup Guide

How Entering, Updating & Changing AWS Keys Works

CloudGate is 100% client-side and read-only. Your AWS credentials are saved strictly on your local machine and never leave your environment.

100% Client-Side Privacy & Zero-Credentials Guarantee STRICT LOCAL SCOPE

The downloadable CloudGate tool contains zero AWS keys, tokens, or credentials. CloudGate executes 100% locally on your terminal and communicates directly with AWS STS & Cloud APIs via the official AWS Boto3 SDK. Your credentials are never uploaded, bundled, or shared with anyone.

01

First-Time Guided Setup

When you run CloudGate for the first time without configured keys, it automatically detects it and launches an interactive credential prompt right in your terminal. Keys are saved to your local ~/.aws/credentials with restricted 0600 permissions:

# Launches guided prompt on first run cloudgate

💡 Prompts for: Access Key ID, Secret Access Key, and Default Region.

02

Updating & Rotating Credentials

Need to rotate your AWS keys or enter new credentials after 90 days? Simply run the built-in configuration wizard anytime to re-enter your keys without altering other tools:

# Reconfigure or update active credentials cloudgate --configure

💡 Or use standard AWS CLI: aws configure

03

Switching Profiles & Accounts

Audit multiple AWS environments (e.g., Staging, Production, Audit) seamlessly without overwriting existing keys by using named AWS profiles or the interactive menu:

# Configure or audit a specific profile cloudgate --configure --profile prod cloudgate --profile prod --hybrid

💡 Or launch interactive menu: cloudgate -i (Option 7)

04

Safe Read-Only IAM Role

CloudGate requires only read permissions (`describe_*`, `get_*`, `list_*`). Attach the AWS managed policy SecurityAudit or deploy our 1-click CloudFormation template:

# Deploy audit role with CloudFormation aws cloudformation deploy --template-file deploy/cloudgate-audit-role.yml ...

Frequently Asked Questions

Everything You Need to Know

Does the downloaded CloudGate tool contain or expose my AWS credentials? +
No, absolutely never. Every archive and file distributed from this website is completely clean and contains zero AWS keys, tokens, account numbers, or personal data. CloudGate runs 100% locally on your computer and reads credentials exclusively from your local ~/.aws/credentials file or environment variables. No keys or scan data are ever transmitted externally.
How do I enter, update, or change my AWS credentials? +
When you launch CloudGate for the first time without credentials, it automatically starts its built-in interactive wizard asking for your AWS Access Key ID, Secret Access Key, and Region. To update expired keys or switch accounts later, simply run cloudgate --configure or choose option 7 in the interactive menu (cloudgate -i). You can also audit multiple accounts using cloudgate --profile <name>.
Does CloudGate ever modify or write to my AWS account? +
No, absolutely never. Every single check performed by CloudGate and Prowler is strictly a read-only AWS API call (`describe_*`, `get_*`, `list_*`). Security group checks read rules via the API — zero network packets are sent to any host.
What AWS permissions does CloudGate require? +
The scanning identity only requires AWS's standard managed SecurityAudit policy (or ViewOnlyAccess). You should never use AdministratorAccess to run security audits.
How does the Prowler integration work? +
CloudGate 2.0 embeds Prowler as its next-stage engine. When you run cloudgate --prowler or cloudgate --hybrid, CloudGate orchestrates Prowler, scopes scans to your active AWS region for maximum speed, ingests the structured OCSF JSON output, deduplicates findings, and generates interactive visual HTML dashboards.
Can I integrate CloudGate into CI/CD pipelines? +
Yes! CloudGate exits with code 0 when gates pass and non-zero when critical or high risks exist, making it an ideal pre-merge or pre-logout gatekeeper in GitHub Actions, GitLab CI, or pre-commit hooks.
